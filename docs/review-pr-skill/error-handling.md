# review-pr skill エラーハンドリング

親エージェントが skill 実行中に遭遇しうる状況と、その扱い方針。

| 状況 | 対応 |
|---|---|
| 対象 PR が見つからない | エラーで終了し、PR 作成か番号指定を促す |
| gh 認証失敗 | `gh auth status` を案内（remote は github.com） |
| subagent の応答が不正な JSON | リトライ 1 回。2 回目も失敗なら生応答を出して終了 |
| 指摘ゼロ | トップレベルのみ投稿、インラインはスキップ |
| インライン投稿失敗（該当 line が diff に無い等） | その 1 件をスキップして続行、失敗件数を報告 |
| 大規模 diff（context に収まらない） | 重要ファイル優先で渡し、「一部は概観のみ」と明記 |
| API レート制限 | 待ってリトライ、駄目なら通知 |

## 方針の要点

- **全体を失敗扱いにしない**。インライン 1 件が投稿できなくても、できる範囲で投稿を完了し、失敗件数を CLI に報告する。
- **不正 JSON のリトライは 1 回まで**。粘りすぎず、駄目なら生応答を見せて人間に委ねる。
- **指摘ゼロは正常系**として扱う（要約・影響範囲・観点は残るのでトップレベルは投稿する）。
