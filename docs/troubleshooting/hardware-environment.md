# ハード・環境のつまづき記録

実装以前の段階（書き込み・環境構築）でハマった問題の記録。根拠は開発セッションの会話記録（2026-06-04）。引用は当時の発言の原文ママ。

## 1. USB で M5 に書き込めない（充電専用ケーブル + ドック経由）

- **問題**: ケーブルを 3 本試しても、`pio device list` / `system_profiler` に M5 Core2 の UART チップ（CH9102）が一切出てこない。書き込み以前にデバイスが見えない。

  > 「もう一つ繋げたけどこれも充電八日な」
  > 「でもこの前の実装ではドック経由でできてたけど？」
  > 「前のケーブルを無くしたから検証してんねんやちお」
- **原因**: 「画面は点く（= 給電は OK）がデータ線が無い」充電専用ケーブルだったことと、ドック経由の接続が重なっていた。以前動いていた実績が「ドックでもいけるはず」という思い込みになり、切り分けを遅らせた。
- **対処**: USB-C to C ケーブルで Mac に**直結**したところ、一発で `/dev/cu.usbserial-54780284771` を検出。
- **発見・教訓**:
  - 「画面が点くのに認識しない」は充電専用ケーブルの典型症状。USB トラブルはまず「ケーブル（データ線あり）+ 直結」で最小構成にして切り分ける。
  - 「前は動いた」は構成が同じ保証にならない（ケーブルを紛失して別物を使っていた）。

## 2. VOICEVOX が Homebrew で入らない

- **問題**: ずんだもん音声の合成に使う VOICEVOX を自動セットアップしようとしたが、Homebrew に cask が無くインストールできない。
- **対処**: 二段構え。
  1. まず macOS 標準の `say` コマンドで音声経路（合成 → M5 のスピーカー再生）を先に確認。
  2. 後から VOICEVOX を Docker で導入し差し替え。`say` は VOICEVOX 未起動時の自動フォールバックとして恒久化した。

  ```bash
  docker run --rm -d -p 50021:50021 --name voicevox voicevox/voicevox_engine:cpu-latest
  ```
- **発見・教訓**: 外部依存（VOICEVOX）が入らなくても、代替（`say`）で経路全体を先に通すと検証が止まらない。その代替はそのままフォールバック機構として本番の堅牢性に転用できた。

## 3. 細かい環境系

- **スピーカー音量が小さい**: M5 の `setVolume` を 180 → 255 に引き上げて解消。
- **シリアルログが出ない**: `M5.begin()` は `Serial.begin()` を呼ばないため、デバッグログが何も出なかった。シリアルに固執せず HTTP `/state` に診断情報を載せる方式へ切り替えた（詳細は [`touch-gesture.md`](touch-gesture.md)）。
